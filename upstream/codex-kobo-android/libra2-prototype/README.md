## 已完成的实机验证

- 三个临时内核模块正常装载与卸载。
- Binder 协议 7、映射、线程参数、空事务 ioctl，以及 Android 原生服务管理器和真实服务列表事务。
- ashmem 命名、大小、映射、跨进程共享写入。
- VM 辅助模块的页面丢弃、私有文件重新载入、范围校验及真实 VMA 提示。
- 实机默认网络观察器识别 wlan0；普通 UID 的原生网络协议正反测试、Android 活动网络查询及两类网络回调均通过。
- Bionic shell、ART、Android 框架服务和自有阅读应用引导通过。
- 真实 Android 四目标窗口以 632×840 显示，1、2、3、4 的实际点击回调全部通过，用户确认；退出后画面字节恢复和全部资源清理通过。
- 首次触控测试只有按下及取消，没有有效松开。控制事件记录证实 Elan 在按住期间会重复报告相同触点编号；已取消错误的额外手指判断。修复后完成 4 个手势，阻断帧为 0。
- 新几何显示桥的首次 GC16 刷新、后续 REAGL 刷新、原 framebuffer 字节恢复、两个 KOReader 进程恢复运行。

人工触控校准已通过；用户已确认微信读书保留登录、正文翻页、书架返回及重开、上键下一页/下键上一页、退出返回 KOReader 均正常。长时稳定性仍待验证。首次启动测试曾因缺少自有诊断程序而退出 127；已补齐程序，重新启动后上述框架与网络检查通过。

## 内核来源与 ABI 校验

官方源码：[Kobo-Reader / hw/imx6sll-libra2/kernel.tar.bz2](https://github.com/kobolabs/Kobo-Reader/blob/master/hw/imx6sll-libra2/kernel.tar.bz2)。

下载归档 SHA-256：`6f8c5693a47b11ff9bcf96401a576a410dd6b13bd7df7e3700e9feaee4363b38`。

使用实机 `/proc/config.gz`，仅构建所需模块；不写入内核或分区。Binder 编译启用 `CONFIG_ANDROID_BINDER_IPC_32BIT`。所需的 99 个导入符号 CRC 均来自对应源码编译产物，其中与实机现有 Wi-Fi 模块可比较的 81 项全部一致；未使用强制装载或伪造 CRC。

## 构建

`build-native.sh` 要求 `KOBO_ZIG_ROOT`、`KOBO_FBINK_ROOT`、`KOBO_ANDROID_ROOT`、`KOBO_BUILD_OUT`。通过 `KOBO_TARGET_LIBRA2` 选择独立的几何和触控配置，Forma 默认配置保持原值。

`build-java.sh` 要求 `KOBO_JAVA_HOME`、`KOBO_ANDROID_JAR`、`KOBO_D8_JAR`、`KOBO_BUILD_OUT`。采用包含无障碍服务和焦点校验的 94 版框架基线，不引入 96 版实验采样服务；输入端从实际 Android display 取得边界。

APK、包含账号的运行镜像和阅读数据不在此源码包内。

## 原生分辨率短时实测

独立实验组件以 1264×1680、320 DPI 运行微信读书，Android 窗口缩放系数为 1.0，直接映射屏幕像素；等效布局仍为 632×840 dp。保留 REAGL 和文字增强。用户确认阅读操作正常，并明确反馈正文比此前整数两倍放大“明显更清楚”。

本轮正常通过双键长按退出，画面精确恢复、KOReader 恢复、进程及模块/挂载/loop 清理均通过。内存监测最低可用 194140 KiB，未触发低内存退出。八个常规版本文件 SHA-256 均保持原值。实验启动早期曾选错属性服务权限版本，已改用经过验证的 root/system 服务。

菜单现提供“原生清晰阅读”的三分钟及最长三十分钟入口，并保留“旧版两倍放大（回退）”。已在设备上检查 Lua 语法与启动器参数边界；需重新打开 KOReader 载入。用户已从重开的 KOReader 菜单成功启动原生三十分钟入口，完成约 11 分钟实际交互，确认翻页、注释、书架切换、全刷及退出均正常。设备记录实际交互 665.55 秒、41 个触控手势、退出码 0；最低可用内存 170556 KiB，未触发低内存退出；画面恢复和全部资源清理通过。完整三十分钟持续运行及性能对照仍待验证，不能据本轮推断启动或翻页速度提升。构建原生实验使用 `build-native-resolution.sh`，结果见 `native-resolution-verification.json`。
