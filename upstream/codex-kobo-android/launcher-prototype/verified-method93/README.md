# 第 93 轮：有界方法调用采样

第 92 轮未能证实明显提速，本轮恢复默认堆设置和 30Hz，保留原 APK、odex、JIT 和动画。通过真实 Android IActivityManager.profileControl 接口请求 ART 100ms 间隔采样，固定目标微信读书主进程，120 秒后请求停止。它是诊断采样，不是逐方法插桩、预编译、APK 改写或性能修复。

先用本项目的 smoke 应用做一秒实机自测，验证接口和输出格式；通过后才采微信读书。采样器需 root，绑定当前就绪文件完整内容，要求至少 140MiB 镜像可用空间；结束后请求停止，运行会话消失即退出。默认 ART 跟踪缓冲为 8MiB，样本和方法名只写 root 0600 的私有 trace 文件，原始文件不包含在源码包中。

采样有额外开销，这一轮不比较人工速度，也不以单点线程栈代替全阶段热点。Java 源码已通过 API24 编译、D8 构建；真实接口一秒自测通过：ART trace 第 3 版、14 字节记录、22 条记录，未溢出，记录长度校验通过。微信读书采样已完成。

实际采样约 129.9 秒：应用主线程稍后才处理停止消息，因此控制器请求时限不是精确采样时长。文件 1,429,950 字节，64,447 条完整记录，无缓冲溢出；还原时调用栈出入全部匹配。少量动态方法 ID 无名称映射，保留为 unresolved，不补造方法名称。

主线程约 43.7 秒为消息队列等待，Binder 顶层累计约 22.2 秒，包含多个调用及采样扰动。一个明确路径是 View/TextView 在创建、布局、可见性变化时，通过 AccessibilityManager 反复查找缺失的 accessibility 服务；累计 getService 采样约 5.6 秒，线程 CPU 约 1.7 秒。第 94 轮优先补齐真实服务，让客户端正常接入并缓存，尚未宣称能节约确定秒数。电池广播查询另有约 5.9 秒累计等待，仍需关联服务端；没有伪造电池数据或改变广播权限。

采样文件保存后，按会话元数据核验触控桥 PID、启动时间及可执行文件，正常结束窗口，exit 0。严格清理审计确认实验进程、模块、挂载及循环设备均已清理，两个原 KOReader 进程恢复。
