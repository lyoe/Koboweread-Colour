# KOReader 本机启动入口（实验）

当前 Android 环境与运行缓存保留第 80 版，显示使用已获确认的 REAGL＋文字增强。五秒真实退出/恢复交接已通过，第 85 版真实阅读因触控依赖检查遗漏而退出，第 86 版修复后，用户确认独立阅读及返回正常，约 91 秒主动退出和清理通过；完整时限与加速效果待验证，见 [独立运行实验](handoff-prototype/README.md)。常规入口仍使用暂停模式。触控、刷新和校验缓存的实测结果及稳定性边界见 [性能优化记录](verified-speed80/README.md)。正常 reading 复用启动允许命中固定 APK 属性绑定缓存，但每轮仍由 PMS 核对 UID 和原签名；缓存失效时重新完整计算两份 APK 的 SHA-256。下文早期版本的“每次完整字节校验”说明由此项更新。


当前第 77 版按键：上键短按下一页，下键短按上一页；任一键按住 1 秒后松开全刷，不额外翻页。双键按住 2 秒后全部松开退出。新版操作说明需重开 KOReader 载入，用户已确认单键长按与新方向全部正常，日志记录 16 次翻页、3 次实际全刷和双键退出，清理通过。见 [第 77 版记录](verified-daily-controls-v77/README.md)。

已为当前 Forma 的既有私有运行环境增加独立 KOReader 插件 `wereadlab.koplugin`，以及设备本地启动脚本。启动文件无需电脑、SSH 会话、手机或远程渲染服务；登录和下载仍需要 Wi-Fi。它运行已经安装并核对身份的原始微信读书 APK，尚不提供通用 APK 安装界面。

退出并重新打开 KOReader 后，在工具菜单中查找 **微信读书（测试）**，选择 **启动阅读（最长30分钟）**，或保留的 **三分钟测试**。通常需几分钟完成初始化；长按屏幕左上角两秒后松手，可提前返回 KOReader。也可在子菜单中查看运行状态。保持设备唤醒和 Wi-Fi 连接。用户已确认实际菜单启动、注释打开、翻页及书架返回再开书均正常；第 63 轮完整运行与清理退出 0。也已确认断开电脑 SSH 后仍继续运行。

这是有界实验入口。30 分钟模式已同步延长触控、显示、Java 输入和网络组件的时限，用户已确认阅读和手动退出正常，设备记录退出码 0；完整 30 分钟连续运行尚未验证，见 verified-long-session。返回 KOReader 后再使用休眠。

安装新增以下文件，没有修改原厂启动配置、现有插件或 NickelMenu 配置：

- `/mnt/onboard/.adds/koreader/plugins/wereadlab.koplugin/{main.lua,_meta.lua}`
- `/mnt/onboard/.adds/kobo-android-lab/launch-weread.sh`
- `/mnt/onboard/.adds/kobo-android-lab/run-weread-session.sh`（来自 framework-prototype 的当前 WebView 软件输出测试外层脚本）
- `/mnt/onboard/.adds/kobo-android-lab/session-status.sh`
- `/mnt/onboard/.adds/kobo-android-lab/fd-clean-exec`（activity-prototype 中同名自制 C 源码的静态 ARM 构建）

插件通过设备 `setsid` 启动本地脚本，先关闭继承的多余描述符；运行环境使用固定选项及清理后的环境变量。PID、进程启动时刻及 boot ID 防止重复启动和错误识别重启前的锁。既有运行外层继续拒绝同时挂载。这个入口仍依赖当前设备此前已配置的私有镜像及组件，不是新设备的一键安装包。

启动状态为 starting/running/restoring/complete/failed。完整运行日志只保存在设备 `weread-launch-private.log` 及一个 previous 版本中，可能含个人应用信息，不在菜单中展示，也不随源码分发。应用账号和书籍数据继续保存在私有镜像内。移除本入口只需在未运行时删除上述新增文件及插件目录；不要删除私有镜像或备份。

最新修复：运行层显式设置共享 Android 路径的创建掩码，临时原生库目录显式设置可遍历权限；单个触控事件被拒绝时取消该手势并继续服务。详见 verified-menu-startup。


## 日常阅读启动配置

菜单显式传入 `KOBO_WEREAD_STARTUP_PROFILE=reading`，仅在复用已安装 APK 且开启交互模式时允许使用。日常启动跳过虚拟内存、虚拟 framebuffer、installd 创建/销毁测试，跳过 UID 10000 的外网站点 DNS/HTTPS 自测，以及诊断 PNG 截图。这样外网站点或 DNS 自测失败不会直接阻止进入阅读；应用仍通过实际宿主网络访问内容，网络断开时可能无法下载和同步。DNS、网络状态观察、TLS 证书检查没有替换成成功结果。

框架/AMS/PMS 启动、原 APK 完整字节身份校验、进程身份、描述符审计、实际 Activity 显示和触控窗口归属检查继续执行。正常阅读的已有 APK 启动调用与显示观察各允许最多 120 秒；应用崩溃及组件退出的失败检查仍保留。未传入配置时仍使用原来的完整开发诊断流程。

日志新增 runtime_begin、framework_begin、app_launch_begin、interactive_ready 的单调时钟时间点，用于区分初始化与微信读书启动耗时，不采集页面内容。当前优化不代表已经实现快速启动。


## 跳过测试页面及连续启动验证

日常 reading-server 仍使用真实 AMS systemReady 与引导应用 attach；自制引导 APK 不再安排测试 Activity。已通过用户开书、翻页和退出验证，框架阶段单次测得约 29 秒。原 APK 源文件重复哈希已合并，源与已安装文件的完整校验仍保留。不同启动页、缓存和网络会影响总耗时，不能用一次两分钟结果承诺每次两分钟。

新增“连续启动验证（10轮）”，仅供验证启动稳定性。每轮进入实际可交互界面后停留约十秒，由开发控制器请求退出，再完整启动下一轮；不注入点击，不打开书籍，不改变账号。任一轮失败即停止，长按左上角退出会停止整组。验证控制器全程保留锁和临时防休眠引用。摘要保存在设备 startup-validation-result.txt，不含账号或书籍画面；原始日志仍仅保留本地最近两轮。完整阅读与网络异常场景需要另外验证。


菜单“查看运行状态”现可显示准备环境、初始化、校验并打开应用等阶段及本轮已等待秒数。十轮模式还显示轮次；失败状态会区分初始化超时、界面超时、应用崩溃、触控中断和可用空间不足，并保留错误码。旧状态文件仍可读取。状态观察仅解析固定阶段，不依赖日志中的账号、书名或页面内容。
