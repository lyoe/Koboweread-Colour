当前部署三分钟独立阅读实验：重开 KOReader 载入新菜单后，进入“微信读书（测试）→独立运行（实验）→独立阅读测试（3分钟）”。它先完成同样的保存、退出及重启码检查，再从独立进程会话启动原本机阅读脚本。启动仍可能需要几分钟，三分钟从交互就绪后计算。双键按住两秒并全部松开可提前结束，或等待窗口结束，随后清理运行环境并重开 KOReader。常规最长 30 分钟入口仍使用已验证的暂停模式。真实独立 APK 阅读已获确认，速度收益仍待重复对比。

显示桥接只在根用户私有交接记录有效时允许没有 KOReader 阅读进程：核对 boot ID、监护程序和启动器的 PID/启动时刻/执行文件/UID、启动器暂停状态，以及当前进程属于受控阅读会话，并检查没有 KOReader 或 Nickel。普通入口仍要求精确识别两个 KOReader 进程。没有修改原 KOReader 启动脚本，也不强制终止真实 KOReader 界面。

监护程序先分叉独立守护，再暂停启动器。阅读子进程在单独会话中等待管道放行，只有根用户 0600 交接记录写入成功才开始运行。正常结束先确认该会话及私有运行镜像下的执行进程全部退出，再恢复启动器。控制进程意外结束或达到总保护期限（900 秒）时，独立守护请求结束阅读；必要时只向所属会话成员发信号，核对其启动标识，确认安静后才恢复启动器。无法确认清理时记录失败并保留现场，不在未知进程上强制卸载或覆盖记录。异常路径可能需要通过 SSH 维护；未进行真实 Android 崩溃或断电恢复测试。

当前设备子进程自测已通过：旧模式超时恢复、控制进程 SIGKILL 后恢复、启动时刻不匹配时拒绝信号；新模式中受控会话及子进程清理、真实守护代码在控制进程 SIGKILL 后先清理会话再恢复目标。租约测试覆盖文件缺失、权限错误、符号链接、旧 boot ID 和无效进程。所有强制结束测试只操作自行创建的测试子进程。无界面 Lua 测试通过准备握手、保存后重启顺序、固定阅读模式、忙碌拒绝、过期记录、准备超时、结果显示，以及原进度、待机策略和显示菜单回归。
