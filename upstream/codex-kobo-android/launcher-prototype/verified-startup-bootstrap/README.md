# 无测试页面的阅读引导与连续启动验证

reading-server 保留原有系统服务、PMS、AMS、引导应用进程创建和 ApplicationThread attach。自制引导 APK 等待 AMS ready 后，在 reading 配置中仅记录 APK_READING_APPLICATION_READY，不安排测试 Activity。若 Android 自动打开 HOME，该 HOME 也不会安排测试页面。完整诊断配置继续使用原来的测试生命周期。

微信读书 APK 未修改。原文件只完整哈希一次，再与固定 SHA-256 以及已安装文件的完整哈希比较；去掉了以前对原文件的重复计算。所有原有进程身份、实际显示与触控归属检查保留。

首次实机已获用户确认开书、翻页和退出正常，设备退出码 0，8 个手势、25 个事件，无跳过或拒绝事件，原 framebuffer 恢复字节一致。进入书架时，运行脚本至交互 117.77 秒，框架阶段 28.83 秒；完整 APK 双文件哈希 10.482 秒。前一轮运行进入阅读页、共 178.10 秒，页面和缓存条件不同，不能将约 60 秒总差异全部归因于本次修改。前一轮框架阶段 42.42 秒。

新增“连续启动验证（10轮）”入口：每轮完整冷启动 Android 进程，验证实际交互就绪，停留约十秒后由开发控制器请求退出，再启动下一轮。全程不注入点击。任一轮失败即停止；真实左上角长按退出会停止整组验证。控制器在整组期间保留同一个锁和 PID，KOReader 插件保持临时防休眠引用，结束后恢复原有策略。正常阅读入口仍为 3/30 分钟。

隔离控制器测试已通过十轮循环、重复启动锁、第三轮故障停止和用户退出停止，但其使用 /tmp 假运行器，不是真机十轮启动通过的证据。真实连续验证现已完成：10/10 启动、显示及触控通道就绪、开发控制器退出与原画面恢复均通过；最终检查无残留 Android 进程、模块或镜像挂载。


## 十轮实机结果

启动耗时按 runtime_begin 至 interactive_ready 的单调时钟差计算，外层入口另需约两秒选择已核对的 WebView 组件。十轮最快 132.57 秒，最慢 156.79 秒，中位数 150.70 秒，平均 146.91 秒；逐轮数据见 ten-startup-results.json 和 ten-startup-summary.txt。十轮均无 Java FATAL EXCEPTION 或原生 Fatal signal，原画面恢复字节检查均通过。原 APK 字节身份逐轮核对，未安排测试 Activity，未进行诊断截图或外网站点联网预检。

这是同一次设备开机中的十次 Android 进程冷启动，不是重启 Kobo 十次。控制器每轮停留约十秒后退出，不注入点击；没有逐轮开书或翻页，不能替代完整 30 分钟连续阅读、网络异常或休眠验证。另一次用户实际开书、翻页和手动退出已经通过，见 verification.json。

本组通过设备本机 CLI 启动，电脑只读取状态和保存记录。设备原有自动休眠/待机配置已关闭，自动关机时限为三天；没有改动这些设置。电脑观察连接曾重新建立一次，设备端验证继续完成；不据此宣称网络连续性或离线阅读已验证。

benchmark-launcher.sh 和 benchmark-component-sha256.json 保存本组基准使用的精确控制器与组件身份。整组结束后安装的状态提示版本仅增加阶段、等待时间、轮次和错误说明；它另外通过设备 Lua 测试、隔离控制器测试与安装语法检查，十轮结果对应前述基准控制器。新提示需重开 KOReader 后载入。
