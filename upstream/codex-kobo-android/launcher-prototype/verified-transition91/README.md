# 第 91 轮：书架切换线程诊断

第 90 轮未能证实 15Hz 加速，本轮恢复默认 30Hz、原动画、原 APK/JIT/odex。此轮用于定位等待，不是性能修复或速度基准。

`watch-black.c` 只读取显示桥已有日志中的帧哈希和时间；发现已知纯黑帧后等待 1.5 秒，最多触发两次，观察最多 180 秒。它绑定启动时的就绪文件身份，运行结束即停止。真实 ARM 静态二进制已编译，设备参数越界拒绝已验证；默认 30Hz 阅读会话已实际就绪，自动采集器已确认进入等待状态；用户已完成操作，两次采集均完成且准确匹配微信读书主进程。

`capture-main.sh` 校验同一运行会话、主进程私有根目录、可执行路径、UID 10007、准确包名和进程启动时间，只向已核对的主进程发送标准 ART SIGQUIT 诊断信号。保留原 Android traces 文件及权限，不截断、不旋转；最多等待四秒，确认对应 PID 的完整结束标志后保存新增内容。输出目录仅 root 可访问，原始线程栈可能含应用信息，留在私有工作目录，不加入公开源码包。

线程诊断可能短暂扰动应用，因此本轮不要求人工计时。无 APK 修改、触控注入或系统服务参数调整。未采集到完整栈前不声明定位到瓶颈。

实机结果：第一次黑帧后约 2.7 秒采到主线程正在创建 HomeFragment、StoreViewModel 和 Compose LazyListState；第二次黑帧后约 1.8 秒采到阅读页 ReaderTimeView 创建时，通过 BatteryUtil 调用 registerReceiver 查询电池状态，主线程等待 Binder 返回。单次快照只能确认采样点，不能给这些调用赋予整个黑屏的持续时间。日志还显示应用主动发起 WeReadFragmentActivity 和 ReaderFragmentActivity 切换；未发现 always_finish_activities 设置项，不能归因于用户启用了“不保留活动”。

两次快照间约 102 秒，主进程累计 GC 次数从 53 增至 117，累计 GC 总耗时从 28.630 秒增至 48.937 秒；累计直接暂停 mutator 时间从 1.104 秒增至 1.682 秒，无阻塞 GC。累计总耗时包含并发阶段及调度等待，不能解释成约 20 秒的直接界面暂停，也不是单次操作耗时。下一步独立试验增加堆空闲余量，尚未宣称定位到唯一瓶颈或修复电池 Binder 等待。

用户退出后完整清理审计通过：无实验进程、挂载、循环设备或模块，两个原 KOReader 进程处于可运行的睡眠状态。随后只读挂载镜像检查历史日志及动画设置，卸载完成；三个动画值仍为 1.0。原始栈和日志仅存于私有工作目录。
