# 第 92 轮：Java 堆空闲余量试验

第 91 轮发现页面切换伴随较多并发 GC。本轮仅在显式启用时为 UID 10007 的微信读书进程设置 `dalvik.vm.heapminfree=4m`、`dalvik.vm.heapmaxfree=8m`。原堆上限和 growth limit、JIT 参数、APK、odex、动画、30Hz 合成、REAGL/GC16 刷新均保持原值。它为分配预留更多空闲空间，可能减少 GC 次数，也可能增加常驻内存；效果待实机人工比较，不能视作已经提速。

普通菜单默认关闭。`KOBO_WEREAD_HEAP_HEADROOM=1` 仅允许固定 reading/reuse/interactive/JIT 组合；根运行器建立 root 私有标记并在清理时移除。属性覆盖只对两项内存属性、固定 UID、标记存在时生效；不影响 UID 0、1000、10000 或其他应用，进程初始化后删除标记不改变已有 VM 参数。微信读书主进程及其同 UID 阅读子进程均在范围内。

验证：主机 C 测试覆盖启用/关闭、各 UID 隔离、无关属性回退、JIT 和堆上限保持原值。真实 ARM/Bionic 测试使用生产库，分别验证 UID 10007 基线、启用、UID 0 隔离、移除标记后回退，四项通过；临时探针、挂载及标记已清理，原组件已备份。没有改写 Android 属性区或 APK。脚本语法检查通过。实际阅读会话已就绪，根标记权限和启用日志已核对。启动阶段 GC 日志显示回收后约 17MB/33MB（47% 空闲）；人工反馈：首次开书 28 秒（黑屏 21 秒）、返回 8 秒（黑屏 2 秒）；再次开书 15 秒（黑屏 9 秒）、返回 8 秒（黑屏 1.5 秒）。重复切换与原版接近，尚无明确提速证据；下一轮已关闭堆余量试验，回到默认参数。

保留 `jit-config-before92.c` 便于复核原默认行为。二进制、APK、应用线程栈、书库和账号日志不在源码包中。

显示桥对应记录为 21.508、2.129、9.091、1.661 秒的纯黑帧间隔，与用户观察相符。前两次开书黑屏期主进程平均约 51.3% / 71.4% 单核 CPU，分词子进程约 15.6% / 0.4%，合成器约 0.5% / 1.1%；本轮采样期间可用内存最低约 197.5MiB。不能把进程 CPU 占比等同于该进程独占造成的等待时间。人工退出 exit 0，实验进程、模块、挂载、循环设备完整清理，KOReader 恢复。
