# 第 88 版：窗口切换时的输入边界修复

第 87 版未通过：首次开书约 32 秒，返回书架时退出 129。日志记录输入调度超时，原因是触控窗口暂停；触控适配器有一次事件被拒绝，随后按旧逻辑追加取消事件。收到的是系统及探针线程栈，未获取有效的微信读书 ANR 主线程栈，不能将此前某次 DiffUtil 卡顿当作本轮已证实的原因。更早编译的试验参数已完整撤回。

本轮修正原输入适配层的边界，不延长输入超时，不忽略 ANR。根用户焦点服务在原 WMS 锁下检查实际 InputWindowHandle.paused 和 visible 字段，仅允许可见且未暂停的已核验微信读书窗口。原固定分类查询继续兼容；新增事务同时返回分类与不含内容的递增窗口代号。窗口对象或可接收状态变化时，代号失效。

触控开始时记录代号，后续事件核对同一可用窗口；切换中丢弃该手势余下部分，不向新窗口重放。事件被拒绝及连接结束时，只有原窗口仍可用才尝试取消，避免把补发取消事件送进已经暂停或替换的窗口。该检查与注入仍是分离调用，不能声称完全消除其间的竞态；需要实际回归验证。

使用当前匹配 services.odex 的内存分析副本核对 WindowState.mInputWindowHandle 与 InputWindowHandle.paused/visible 字段，无修改设备服务包。测试使用生产 LiveFocusService 和自有 WMS 模型，覆盖暂停、隐藏、缺失句柄、窗口替换、恢复后旧手势失效、普通分类兼容及根用户调用限制；旧焦点边界回归通过。Java/D8 构建通过。真实设备已安装新框架与输入探针，已实际启动原 JIT 参数的常规 30 分钟窗口。设备确认新服务注册成功、窗口快照分类 3/代号 1、触控端点就绪；用户已确认反复开书、返回书架正常，时间大致不变；同一窗口后续与第 89 版动画试验合计交互约 595.66 秒，双键主动退出，返回码 0、画面恢复字节一致，私有进程和镜像已清理；复查发现两项引用计数已为零的实验模块仍加载，维护中已卸载。第 90 版增加有界卸载重试和更严格的审计，避免将这种残留误报为完整清理。

原 APK、原 build80 odex、显示文字增强/REAGL、实体键规则和独立模式控制器均保留。当前尚无书架速度提升结论。后续需要分别判断输入稳定性、界面构建耗时和黑色过渡帧，不能把黑屏遮盖当作实际提速。
