# 日常操作第一阶段：Forma 实体键与墨水屏刷新

第 76 版固定支持 1440×1920 竖屏、按键在右侧的 Forma。实际设备 gpio-keys 的键码 193/194 对应上/下键，参考已安装 KOReader 映射；原微信读书 BookFragment 支持 Android PAGE_UP 92 与 PAGE_DOWN 93，无需修改原 APK。

- 上键松手：上一页；下键松手：下一页。长按重复事件不产生连翻。
- 两键同时短按、全部松开：请求一次全刷，即使画面内容不变也会刷新。
- 两键同时按住至少两秒、全部松开：退出。左上角长按退出继续保留。
- 运行期间电源键松开：安全退出到 KOReader；本阶段不直接休眠，返回后再按电源键休眠。

实体键仅在确认两个原 KOReader 进程暂停后接管 event0，并核验设备名、支持键及初始按键状态。只向已验证 UID/签名的原微信读书 ReaderFragmentActivity 所属实际焦点窗口发送固定翻页键；书架、弹窗、无焦点及触屏手势期间跳过，不伪造触控坐标。键盘事件使用成对 DOWN/UP，拒绝不记为应用接受。退出关闭 evdev，内核释放独占。

首次显示使用 GC16 全刷；后续仍保持不超过每秒一次的原刷新速率，累计 12 次局刷且距上次全刷至少 15 秒时做周期全刷。双键短按手动请求绕过周期阈值，仍限制显示速率。请求通过 root 私有实验目录中的原子发布文件传递，显示端校验类型、属主、模式和固定内容；不修改驱动参数。

KOReader 插件增加“操作说明”，日常启动期间每十秒或阶段改变时更新进度。点按进度可收起且不再自动弹出，后台启动继续；退出恢复原待机策略。需退出并重新打开 KOReader 载入新版插件。

ControlsTest.c 已对两种组合键顺序、两秒边界、启动时按住、丢弃重复事件、电源键及周期刷新阈值完成断言。ProgressTest.lua 已在设备自带 LuaJIT 的模拟 UI 环境验证阶段更新、节流、关闭回调、帮助及防待机引用生命周期。这些检查不替代实际按键与视觉确认，实机反馈见 verification.json。

本阶段仍保留单次 30 分钟上限。休眠/唤醒、Wi-Fi 自动重连、耗电及其他屏幕方向尚未完成。

实机第 76 轮：用户反馈测试正常，日志确认 7 次实体键翻页接受（前翻 3 次、后翻 4 次），双键长按退出 1 次；实际运行 104.99 秒，退出码 0，原画面恢复字节一致，实验进程/模块/镜像挂载/loop 均已清理，未见 Java/原生崩溃及微信读书 ANR。该轮周期全刷已执行，但手动全刷请求和手动刷新计数均为 0，故未把用户反馈单独作为手动全刷实现通过的证据，已请求补验，同时验证重开 KOReader 后的新菜单与进度。

菜单复测：用户确认菜单、启动进度及全刷全部正常。日志记录 20 次实体翻页、2 次手动全刷请求及 2 次实际手动全刷，双键退出 1 次，运行 53.81 秒，退出 0、画面恢复一致。用户认为双键全刷操作繁琐，要求下一版采用任意单键长按 1 秒全刷，并调换上下键翻页方向；第 76 版按键策略快照留在本目录，旧策略测试引用该快照。
