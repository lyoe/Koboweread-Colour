# 第 87 版：书架编译参数试验未通过，已撤回

原缓存基线人工计时：首次开书约 35 秒，返回书架 8 秒，再次开书 16 秒，再次返回 11 秒；切换期间长时间黑屏，书架部分封面更新。基线运行退出 0、画面恢复与清理正常。

画面日志确认出现完全纯黑的缓冲帧，随后约 22.26 秒、12.76 秒才出现下一幅画面，单次面板刷新约半秒，因此这些长等待不能仅归于波形刷新。此轮尚未改动空白帧显示策略。封面更新本身可能来自正常书架状态更新，尚不能判为缓存失效。

只成功采得一份主进程线程样本：主线程可运行，处于书架封面控件创建、TextView 初始化、RecyclerView 网格布局及 ConstraintLayout 测量路径；当时阅读子进程尚不存在。原计划连续采样的电脑端观察程序在新用户消息进入时中断，不能把单份快照称为完整热点统计，也不能断言它涵盖了所有切换。该样本 JIT 缓存约 295 KiB、513 个条目，已发生三次缓存回收；这是确定试验方向的依据，不是收益测量。

试验针对微信读书 UID 10007，在明确启用时把 JIT 编译门槛设为 2000、初始代码缓存从 256 KiB 调为 1 MiB，最大值继续为 8 MiB。目标是让反复调用的布局、列表相关代码更早进入编译执行；也可能增加早期编译负担，须实际比较。系统服务及探针 UID 不改变，普通启动不启用此参数。第 80 版原运行缓存及原 APK 保留，未安装第 82 版候选。

主机配置测试覆盖 UID、标记文件、普通参数、固定最大值和其他属性回退。设备实际 ART 测试使用只在离线维护期间临时绑定的专用探针库，将相同参数限定给自制探针 UID 10000；解释与编译工作量校验结果相同，实际编译计数通过。它只验证运行配置兼容，不代表书架提速。临时绑定及标记已删除，原 odex SHA 再次核对通过；生产库的 UID 范围仍只有 10007。
