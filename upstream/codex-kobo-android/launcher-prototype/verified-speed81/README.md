# Build 81: bounded AOT experiment

**Rejected for daily use; reverted to build 80's original cache.** Human testing returned to KOReader while returning to the shelf. The runtime logged an input-dispatch ANR and exited 129; the main thread was runnable in `BaseShelfAdapter.diffAndNotify` via shelf offline-status updates. This does not establish an AOT compiler defect, but the candidate showed no measured cold-start gain and failed this regression test, so it is withdrawn. Framebuffer restoration and post-failure process/module/mount cleanup passed. The original cache SHA was verified after restoration, and the restored build 80 has restarted into a real shelf Activity with an active touch window. The human book-open/shelf-return retest is pending. The original remains the daily-use baseline.

Targets the reported book opening and shelf loading delays. The original APK stays unchanged; only its replaceable ARM runtime cache is considered. Build 80 logged two subsequent Reader Activity first frames at 16.091 and 25.071 seconds. These are not complete content loading measurements.

The original 79,614,376-byte cache has a verified private host backup, SHA-256 ac79bb7956ef1852a179d88f49362b0f65acb82c6c0fde0409367f4740d9d6e2. The profile selects 3344 candidate methods using category budgets and per-class limits. It is a preset, not a recorded hot-method profile. Original APK, indices, binary profile, odex and personal logs stay private and are not distributed.

`generate-profile.py` needs Python, androguard and loguru, and takes the original APK and a private output directory. It checks the fixed APK SHA before parsing, writes ART 7 `pro\0/001\0` records using ZIP-entry CRC32 checksums and colon-separated multidex locations, and independently decodes the resulting records. ART 7 ignores `--compiled-methods` for ordinary apps, so this experiment explicitly uses `speed-profile` and `--profile-file`.

`compile-candidate.sh` is a developer maintenance script for this already-configured device, not an installer. It requires the dedicated maintenance mount, no reading session, and the fixed profile SHA. It uses one low-priority compiler thread, a 600-second timeout, output size and space guards, and never installs its output automatically. The first attempt exceeded its 240 MiB RSS guard and was stopped, leaving the original cache intact. The second reduces the compiler heap to 96 MiB, allows at most 300 MiB RSS, and requires at least 96 MiB available memory.

The second compilation completed in 92.95 seconds. The candidate is 80,572,840 bytes, SHA-256 5d4f771b1790c7f24b5e5dafea2f2ac9be5794e64871bcc4810bbc3a2b9439b5, with 692,528 additional bytes in its ELF executable section. All 13 embedded DEX ZIP CRC values, sizes and every non-instruction byte match the original APK. ART quickens instruction operands inside its generated cache, so those embedded instructions are not asserted to be byte-identical. The original APK itself is unchanged. The boot image checksum also matches, and OAT metadata confirms `speed-profile` and position-independent code.

The candidate was installed and its executable mapping observed in real WeRead processes. Cold startup was 121.16 seconds, versus build 80's single cache-hit sample of 119.46 seconds; initial Reader Activity first frame was 38.000 seconds versus 38.624 seconds (total Activity launch 54.712 versus 54.539 seconds). These do not show a meaningful cold-start improvement. Shelf-return regression testing failed; the session did not complete 30 minutes. Native code generation alone does not demonstrate a speedup.

Primary sources: [ART 7 compiler driver](https://android.googlesource.com/platform/art/+/android-7.0.0_r1/compiler/driver/compiler_driver.cc), [offline profile format](https://android.googlesource.com/platform/art/+/android-7.0.0_r1/runtime/jit/offline_profiling_info.cc).
